# Чек-лист: что нужно сделать самому

Этот документ — список ручных шагов, которые Claude Code за тебя не сделает. Делается параллельно или после того, как Claude Code соберёт код.

**Время:** ~3 часа активной работы + сутки ожидания (DNS + прогрев почты).

---

## 1. Купить домен (15 минут, ~200₽)

- Зайти на reg.ru или timeweb.com
- Купить домен в зоне `.ru` — например `tvoya-firma-sales.ru`
- **Не используй свой основной домен** — нужен отдельный, чтобы в случае проблем с репутацией не пострадала основная почта
- На год хватит, не продлевай вперёд

---

## 2. Подключить почту к домену (30 минут + ожидание DNS до 24ч)

Бесплатный вариант — **Mail.ru для Бизнеса**:

1. Зайти на biz.mail.ru
2. Зарегистрировать аккаунт, привязать купленный домен
3. Подтвердить владение доменом — добавить TXT-запись в DNS у регистратора по их инструкции
4. Создать ящик — например `info@tvoya-firma-sales.ru`
5. **Включить «пароль приложения»** в настройках безопасности — он понадобится для SMTP/IMAP, основной пароль не подойдёт

Альтернатива: **Yandex 360 для бизнеса** — на момент написания есть бесплатный тариф, проверь актуальное на 360.yandex.ru/business.

**Zoho Mail** — третий вариант, бесплатно до 5 пользователей, работает из РФ.

---

## 3. Настроить SPF, DKIM, DMARC (20 минут + ожидание DNS)

**Без этих записей письма летят в спам гарантированно.** Это не опционально.

В панели управления DNS у регистратора (reg.ru / timeweb / где купил домен) добавить три TXT-записи:

### SPF (на корневой домен `@`)
```
v=spf1 include:_spf.mail.ru ~all
```
Для Yandex 360: `v=spf1 redirect=_spf.yandex.net`

### DKIM
Mail.ru / Yandex дадут готовую TXT-запись в админке почтового сервиса (обычно на хосте `mailru._domainkey` или `mail._domainkey`). Скопировать её в DNS как есть, дословно.

### DMARC (на поддомен `_dmarc`)
```
v=DMARC1; p=none; rua=mailto:dmarc@tvoya-firma-sales.ru
```
`p=none` = «только мониторинг, ничего не блокировать». На старте этого хватит.

### Проверить
Через 1-24 часа зайди на mxtoolbox.com → ввести домен → должны быть видны все три записи без ошибок. Также проверь на mail-tester.com — отправь туда письмо со своего нового ящика, он даст оценку из 10. Цель: 9+/10.

---

## 4. Прогреть почтовый аккаунт (2-3 недели, по 10 минут в день)

Свежий ящик с непрогретым доменом улетает в спам ко всем получателям. Прогрев = постепенно убедить почтовые сервисы, что ты живой.

- **Неделя 1:** руками отправляй 5-10 писем в день друзьям/коллегам/на свои другие ящики (gmail, yandex, mail). Получатели **должны открыть и ответить** хотя бы на половину.
- **Неделя 2:** 15-20 писем в день, аналогично.
- **Неделя 3:** 30-50 писем в день, можно начать слать первые холодные пробные.

После 3 недель домен «прогрет» — можно переключать в боевой режим на 100/день.

Альтернатива: сервисы автопрогрева (Warmy, Lemwarm) за $20-50/мес. На минимальном бюджете делай руками.

## 5. Получить API-ключи

### 2GIS (обязательно, бесплатно)
1. Регистрация на dev.2gis.ru
2. Создать проект → получить API-ключ для **Catalog API**
3. Бесплатный лимит: 2000 запросов/день (нам с большим запасом)

### Yandex Geocoder (опционально, на v2 проекта)
1. developer.tech.yandex.ru → создать API-ключ для Geocoder API
2. Лимит: 1000 запросов/день
3. Не нужен в первую неделю

## 6. Установить инструменты на ПК (1 час)

На домашнем ПК

```bash
# Docker (для Postgres и Redis)
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
# нужен relogin или newgrp docker

# Python 3.12
sudo pacman -S python python-pip
# либо через uv (рекомендую):
curl -LsSf https://astral.sh/uv/install.sh | sh

# Ollama (для локальной LLM)
curl -fsSL https://ollama.com/install.sh | sh
systemctl --user enable --now ollama

# Скачать модель Qwen 2.5 7B (~4.5 GB)
ollama pull qwen2.5:7b-instruct-q4_K_M
```

Проверить, что Ollama работает:
```bash
ollama run qwen2.5:7b-instruct-q4_K_M "Привет, представься"
```

**Про железо:** твой 1660 Super (6GB VRAM) тянет Q4-квантизацию 7B-модели почти впритык. Если будет OOM — используй ещё более ужатую `qwen2.5:7b-instruct-q3_K_M` (~3.5GB). На рабочем ПК (AMD GPU 2GB) с Ollama ничего серьёзного не выйдет — там либо CPU-режим (медленно), либо вынесенная классификация только на домашнем ПК.

## 7. Заполнить `.env` файл (10 минут)

После того как Claude Code соберёт проект, появится `.env.example`. Скопировать в `.env` и заполнить:

```bash
# Postgres (поднимается через docker-compose)
DB_URL=postgresql+asyncpg://outreach:outreach@localhost:5432/outreach

# Redis
REDIS_URL=redis://localhost:6379

# 2GIS
TWOGIS_API_KEY=твой_ключ_от_2gis

# SMTP (твой ящик на купленном домене)
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=info@tvoya-firma-sales.ru
SMTP_PASSWORD=пароль_приложения_не_основной
SENDER_NAME=Дмитрий Фамилия
SENDER_EMAIL=info@tvoya-firma-sales.ru
REPLY_TO=info@tvoya-firma-sales.ru

# IMAP (тот же ящик)
IMAP_HOST=imap.mail.ru
IMAP_PORT=993
IMAP_USER=info@tvoya-firma-sales.ru
IMAP_PASSWORD=пароль_приложения

# Ollama
OLLAMA_URL=http://localhost:11434
LLM_MODEL=qwen2.5:7b-instruct-q4_K_M

# Поведение
DAILY_SEND_LIMIT=100
WORK_HOURS_START=9
WORK_HOURS_END=18
TIMEZONE=Asia/Yekaterinburg

# Логи
LOG_LEVEL=INFO
```

**Важно:** `SMTP_PASSWORD` и `IMAP_PASSWORD` — это **пароли приложения**, генерируются в настройках безопасности почтового аккаунта. Основной пароль от ящика не подойдёт (Mail.ru/Yandex его не примут для SMTP).

## 8. Написать шаблоны писем (1-2 часа) — самое важное

Шаблоны лежат в `templates_email/trader.txt` и `templates_email/end_user.txt`. Скопируй из `*.txt.example` и перепиши под себя.

### Структура каждого файла
```
Subject: тема письма (без кричащих слов)

{{ greeting }}!

[1-2 предложения с зацепкой — почему пишешь именно им]

[2-3 предложения о том, что предлагаешь — ассортимент, география, условия]

[Призыв к действию: ответить с запросом прайса/спецификации]

С уважением,
Имя Фамилия
Должность
Телефон
Сайт
ИНН: [твой ИНН]

---
Если рассылка вам неинтересна, ответьте «Отписаться» — больше писать не будем.
```

### Что обязательно
- Реквизиты отправителя (ИНН, ИП/ООО)
- Контакты (телефон, сайт)
- Способ отписаться — это требование закона + улучшает репутацию
- Тон деловой, без воды

### Что НЕ нужно
- ❌ Кричащие заголовки в духе «СУПЕР ПРЕДЛОЖЕНИЕ»
- ❌ Слова «бесплатно», «акция», «скидка» в теме (фильтры спама любят их)
- ❌ Прикреплённые файлы и ссылки в первом письме (запрашивать прайс будут уже в ответе)
- ❌ Картинки, баннеры, подписи с логотипами
- ❌ HTML — только plain text. Серьёзно.
- ❌ Эмодзи в теме письма

### Различия trader.txt и end_user.txt

**trader.txt** — трейдерам/перекупщикам:
- Они уже в теме, объяснять, что такое НКТ, не надо
- Фокус: условия поставки, отсрочка, складские остатки, объёмы, география

**end_user.txt** — конечникам (нефтегаз, стройка, ЖКХ):
- Менеджер по снабжению должен сразу понять выгоду
- Фокус: надёжность, сертификаты, опыт, конкретные типоразмеры под их задачи

**Если хочешь — пришли мне свои реквизиты + что конкретно продаёшь (виды труб, география, условия), я набросаю первые версии шаблонов.**

## 9. Запустить и проверить

```bash
cd pipes-outreach
docker compose up -d                 # стартует Postgres + Redis
uv pip install -e .                  # ставит зависимости
alembic upgrade head                 # создаёт таблицы

# Создать кампанию
outreach campaign create --name "Трейдеры тест" --segment trader --template trader

# Прогнать первый цикл на 10 компаниях
outreach discover --source 2gis --query "трубы стальные" --region 38 --limit 10
outreach harvest --limit 10
outreach classify --limit 10

# Посмотреть, что бы улетело — БЕЗ реальной отправки
outreach send --campaign-id 1 --dry-run

# Зайти на дашборд
xdg-open http://localhost:8000
```

Если dry-run выглядит ок — убирай `--dry-run` и запускай боевой send. Начни с 10/день первую неделю, потом увеличивай к 100.

## 10. Ежедневная работа (10 минут в день)

После настройки:

1. Утром заходишь на http://localhost:8000
2. Смотришь графу **«Ответили»** (replied)
3. Открываешь свой почтовый клиент, общаешься с ответившими руками — это уже не автоматизируется
4. Раз в неделю смотришь, какие письма ушли в bounce, подкручиваешь шаблоны, если open rate низкий

Discovery, harvest, classify, send и check_replies крутятся по расписанию через arq или systemd-таймеры — без твоего участия.

## 11. Что делать, если что-то ломается

| Симптом | Что делать |
|---|---|
| Письма уходят в спам | Проверь mxtoolbox.com (SPF/DKIM/DMARC) и mail-tester.com (оценка 9+/10) |
| 2GIS не возвращает данные | Проверь квоту в кабинете dev.2gis.ru, не превышен ли лимит 2000/день |
| Парсер не находит email на сайте | Нормально — не все компании размещают email открыто, пропускай |
| Ollama медленно классифицирует | Нормально для 1660 Super, запускай `outreach classify` ночью |
| Mail.ru блокирует ящик | Слишком быстрая рассылка. Снизь `DAILY_SEND_LIMIT` до 30, прогревай ещё неделю |
| Ollama OOM | Переключись на `qwen2.5:7b-instruct-q3_K_M` или меньшую модель |
| Получатель пишет «отписаться» | Система автоматически пометит — но проверь в дашборде, что unsubscribed=True |

## 12. Юридический минимум

Чтобы не нарваться на жалобы и штрафы по 38-ФЗ:

- ✅ ИП или ООО зарегистрированы официально
- ✅ В каждом письме указан ИНН и контакты для обратной связи
- ✅ Есть способ отписаться, и ты его соблюдаешь — если пометили `unsubscribed=True`, повторно слать нельзя
- ✅ Не шлёшь в госкомпании (по ОКОПФ или префиксу «гос»/«муниц» в названии)
- ✅ Тема письма соответствует содержанию (не «Документы по контракту» с рекламой внутри)

Это не делает рассылку 100% легальной — формально по ст. 18 ФЗ-38 нужно предварительное согласие. Но снижает риски до минимума на твоём масштабе. Я не юрист — для коммерческого роста проконсультируйся с профильным юристом.

## 13. Когда что-то пошло хорошо

Через 2-3 месяца, если открываемость держится 15%+ и ответы 1-3% — можно расширяться:

- Подключить второй адаптер (list-org или Yandex)
- Добавить второй сегмент шаблонов (например, отдельный для нефтесервиса vs строителей)
- Купить второй домен и развести нагрузку (inbox pool)
- Прикрутить пиксельный трекинг открытий (для оптимизации шаблонов)
- Поднять всё на VPS, чтобы не зависеть от того, включён ли домашний ПК
